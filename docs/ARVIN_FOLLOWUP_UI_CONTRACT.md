# ARVIN FOLLOW-UP UI CONTRACT

## هدف
پیاده‌سازی صفحه واقعی جزئیات کار پیگیری‌دار در Flutter بر اساس UI/UX نهایی آروین.

این سند مکمل قراردادهای Task، FollowUp و Quick Entry است.

## معماری
استفاده از هسته موجود پروژه:
- Task
- FollowUp
- Project
- Category
- Tag
- Storage

ساخت مدل، مسیر یا ذخیره‌سازی موازی ممنوع است.

## ظاهر
- فارسی و RTL
- VazirHarf
- رنگ اصلی #4A4CAB
- پس‌زمینه #F8F8FB
- کارت سفید با گوشه نرم و سایه ملایم

صفحه شامل:
- عنوان جزئیات کار
- برگشت و ویرایش
- کارت مشخصات Task
- کارت آخرین پیگیری
- تاریخچه Timeline پیگیری‌ها
- افزودن پیگیری
- انجام کار

## رفتار
- لمس Task کارت، جزئیات را باز کند.
- ویرایش همان شناسه Task را باز کند.
- افزودن پیگیری، رکورد جدید ایجاد کند.
- تاریخ و ساعت فعلی پیش‌فرض و قابل تغییر باشند.
- متن خالی با «پیگیری» ثبت شود.
- خطای ذخیره ورودی را حفظ کند.
- ثبت تکراری جلوگیری شود.

## قوانین داده
- موعد Task، Reminder و زمان FollowUp مستقل هستند.
- FollowUp قبلی حذف یا جایگزین نشود.
- پیگیری بعدی فقط با داده واقعی نمایش داده شود.

## پذیرش
- آخرین پیگیری و تعداد پیگیری‌ها فوری به‌روز شوند.
- داده پس از Restart باقی بماند.
- تاریخچه بر اساس زمان ثبت مرتب باشد.
- UI در اندازه‌های مختلف واکنش‌گرا باشد.
- flutter analyze و تست‌های مرتبط اجرا شوند.
