# REV10 TASK DETAILS CONTRACT — 2026-11-13

REV10-007 supersedes the older manual Edit Mode / Save / Cancel model described below. The active product contract is Single-Column Focus Detail View, Actionable Linear List and Quick Presets. Details are presented vertically from top to bottom; a one-row layout for all fields is not required. Task fields use canonical Auto-Save and must survive close/reopen without data loss. In Task forms, the time icon and calendar icon appear side-by-side in the same row. Center, Project and Category are single-select with clear/search/create/autosave; Tags are multi-select checkboxes with create/autosave; Person must be a real persisted Person relation. Existing storage and repositories are reused; no parallel model/store.

## 1. هدف و اصل تعامل
صفحه مشخصات کار یک فرم جامع و واحد است که دو حالت نمایش و ویرایش داخلی دارد (Single Form View/Edit Mode). کاربر برای ویرایش وارد صفحه یا دیالوگ جداگانه نمی‌شود. لمس مداد در هدر، همان صفحه و همان فیلدها را به کنترل‌های ویرایشی تبدیل می‌کند. ترتیب بخش‌ها، جایگاه عناصر و موقعیت اسکرول باید دقیقاً حفظ شود؛ تغییر حالت نباید کاربر را به ابتدای صفحه بفرستد یا ساختار را جابه‌جا کند.
- حالت نمایش: اطلاعات خوانا، کارت‌محور و تعاملی؛ کنترل‌هایی مانند چک‌باکس چک‌لیست در صورت مجاز بودن قابل استفاده‌اند.
- حالت ویرایش: فیلدهای همان صفحه editable می‌شوند؛ ترتیب ۱۱ بخش ثابت می‌ماند.
- ذخیره: آیکون تأیید در هدر، تغییرات را ثبت می‌کند.
- لغو: دکمه لغو، تغییرات ذخیره‌نشده را کنار می‌گذارد و مقادیر پایدار قبلی را بازمی‌گرداند.
- تغییر حالت نباید باعث ایجاد رکورد موازی، کپی مدل یا تغییر ناخواسته داده شود.

## 2. ترتیب قطعی ۱۱ بخش از بالا به پایین

### 2.1 هدر
- راست: فلش بازگشت.
- مرکز: عنوان «مشخصات کار».
- چپ در نمایش: آیکون مداد برای ورود به ویرایش.
- چپ در ویرایش: آیکون تأیید/ذخیره و دکمه لغو.
- منوی سه‌نقطه برای عملیات فرعی در هدر باقی می‌ماند و جایگزین عملیات اصلی ذخیره/لغو نیست.

### 2.2 پنج کارت اطلاعاتی افقی
بلافاصله زیر هدر؛ ردیف افقی RTL و در عرض کم قابل اسکرول. هر پنج کارت هم‌اندازه، با رنگ معنایی ملایم و عنوان بالای مقدار:
1. زمان اجرا — آیکون تقویم.
2. مرکز — آیکون مرکز.
3. پروژه — آیکون پوشه.
4. دسته — آیکون چهارخانه.
5. برچسب‌ها — آیکون تگ.

این کارت‌ها خلاصه متادیتا هستند و باید به داده canonical موجود متصل شوند؛ ساخت مخزن، مدل یا رابطه موازی ممنوع است. برای «زمان اجرا» هیچ timestampی از `createdAt` یا `dueDate` حدس زده نشود. وجود و معنای فیلد canonical متناظر باید در مدل/مخزن تأیید شود؛ تا آن زمان مقدار آن NOT VERIFIED/نامشخص است. مرکز/پروژه/دسته/برچسب نیز فقط در صورت وجود رابطه و مقدار واقعی نمایش داده شوند.

### 2.3 کارت اصلی هویت کار
- عنوان Task درشت و Bold.
- نشان وضعیت با رنگ معنایی: «در انتظار انجام» بنفش، «در انتظار پاسخ» نارنجی، «انجام‌شده» سبز.
- نشان اهمیت: زیاد، متوسط، کم، بدون اولویت؛ رنگ‌ها متمایز و با کنتراست خوانا.
- توضیحات کامل کار در همین کارت.
- برچسب وضعیت و اهمیت فقط presentation هستند و باید به enum/مقادیر canonical فعلی متصل بمانند؛ کدهای داخلی یا اولویت‌های موازی ساخته نشوند.

### 2.4 کارت موعد انجام (Due Date)
- تاریخ شمسی خوانا و ساعت در صورت وجود.
- سوئیچ تمام‌روز.
- انتخاب تاریخ با تقویم شمسی آروین و ساعت با Universal Arvin Time Picker.
- Due Date فقط موعد انجام Task است؛ از تاریخ Reminder یا تاریخ Follow-up مقداردهی/جایگزین نشود.
- در صورت نبود تاریخ یا ساعت، مقدار خالی به‌صورت صادقانه نمایش داده شود؛ پیش‌فرض اجباری نسازید.

### 2.5 کارت مسئول
- رابط محصولی برای انتخاب/نمایش مسئول در این بخش قرار می‌گیرد.
- اتصال باید فقط از رابطه canonical مدل Task و داده `Task.people` استفاده کند؛ موجودیت مسئول، جدول یا مخزن موازی ممنوع است.
- قید ممیزی: وجود people مرتبط به‌تنهایی اثبات نمی‌کند که آن شخص «مسئول» تعیین شده است. تا زمانی که معنای assignment در مدل و مسیر ذخیره‌سازی تأیید نشده، شخص مرتبط نباید خودکار به‌عنوان مسئول معرفی شود؛ وضعیت این نگاشت NOT VERIFIED است.

### 2.6 کارت یادآوری‌ها
- یادآوری اصلی و یادآورهای مستقل در ردیف‌های کارت‌مانند جداگانه نمایش داده شوند.
- هر Reminder شناسه، زمان، وضعیت فعال/غیرفعال و عملیات مجاز خودش را حفظ کند.
- Reminder مستقل از Task Due Date و تاریخچه Follow-up است.
- مفهوم موازی «Next Follow-up» ایجاد نشود. اقدام آینده فقط با Reminder استاندارد و مستقل نمایش/زمان‌بندی می‌شود.
- خاموش‌کردن Reminder نباید Task را انجام‌شده کند و انجام Task نباید به‌صورت ضمنی تاریخچه Follow-up را تغییر دهد.

### 2.7 کارت تکرار کار
- در حالت غیرفعال، خلاصه‌ای کوتاه و کم‌ارتفاع نمایش داده شود.
- در حالت ویرایش، نوع تکرار، بازه/فاصله، شمارش یا پایان و تنظیمات canonical موجود قابل تنظیم باشد.
- پیش‌نمایش occurrenceها صرفاً projection است؛ نباید برای هر پیش‌نمایش Task یا Reminder واقعی و تکراری ساخته شود.
- قرارداد recurrence موجود و داده‌های پایدار مرجع‌اند؛ مدل موازی ایجاد نشود.

### 2.8 کارت چک‌لیست
- چک‌لیست عمومی و قابل استفاده برای همه Taskهاست؛ محدود به قالب خاصی از کار نیست.
- در حالت نمایش: شمارنده انجام‌شده/کل، نوار پیشرفت و چک‌باکس تعاملی هر مورد.
- در حالت ویرایش: افزودن، تغییر متن، حذف، تغییر وضعیت و مرتب‌سازی موارد.
- تغییر یک مورد نباید سایر موارد یا تاریخچه Follow-up را تخریب کند.
- اولویت بصری این کارت بالاست؛ پیشرفت باید سریع و بدون ورود به حالت ویرایش قابل فهم باشد.

### 2.9 کارت آخرین پیگیری
- کارت با تمایز بصری و برجستگی بیشتر از کارت‌های عادی.
- شامل عنوان اقدام، یادداشت، زمان واقعی ثبت، نتیجه، وضعیت «در انتظار پاسخ» و زمان سپری‌شده پویا از همان رویداد واقعی.
- محاسبه زمان سپری‌شده از `FollowUp.dateTime` انجام شود؛ زمان کلیک، زمان بازشدن صفحه یا `createdAt` جایگزین نشود.
- اگر رکوردی وجود ندارد، دقیقاً نمایش داده شود: «هنوز پیگیری ثبت نشده است».
- Follow-up یک رویداد تاریخی است؛ زمان‌بندی آینده در آن تعبیه نشود.

### 2.10 تاریخچه پیگیری‌ها
- تایم‌لاین عمودی با جدیدترین رکورد در بالا (ترتیب نزولی بر اساس زمان واقعی Follow-up).
- هر ردیف: نقطه زمانی، عنوان، جزئیات/یادداشت، فاصله زمانی و منوی عملیات.
- ویرایش یک رکورد سابقه نباید رکوردهای دیگر را حذف، بازنویسی یا جابه‌جا کند؛ ترتیب پس از ویرایش بر اساس timestamp canonical دوباره محاسبه می‌شود.
- منبع زمان canonical هر Follow-up برابر `FollowUp.dateTime` است؛ `completedAt` در قرارداد فعلی alias سازگاری است، نه فیلد persisted مستقل.

### 2.11 نوار عملیات ثابت پایین
- نوار در پایین صفحه ثابت و مستقل از اسکرول محتواست.
- دکمه اصلی و برجسته: «افزودن پیگیری» با رنگ اصلی.
- دکمه ثانویه با کادر مشخص: «انجام کار»؛ پس از تکمیل به «بازگشت به انجام‌نشده» تبدیل می‌شود.
- «افزودن پیگیری» فرم ثبت رویداد تاریخی را باز می‌کند؛ فقط پس از ذخیره صریح، رکورد به تاریخچه اضافه می‌شود.
- «انجام کار» فقط وضعیت Task را تغییر می‌دهد؛ Follow-up یا Reminder را به‌صورت ضمنی ایجاد/حذف نمی‌کند.
