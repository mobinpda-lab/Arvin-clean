# ARVIN FINAL UI VISUAL REFERENCE

## Status
Canonical product design authority document.

Version: 1.0
Source authority: Real installed Arvin application screenshots and approved product direction.

## Purpose
This document defines the visual and interaction reference for Arvin. Future UI implementation must match this reference. Conflicting old UI documents are superseded.

## Authority Rules

1. Real installed Arvin application behavior and approved screenshots are the primary reference.
2. Existing documentation is valid only when it does not conflict with this document.
3. Old experiments, mockups and abandoned layouts must not redirect implementation.

# Product Identity

Arvin is a Persian RTL productivity application focused on:

- Work management
- Follow-up tracking
- Notes
- Checklists
- Projects
- Categories
- Labels
- Calendar planning
- Fast task capture

# Visual System

## Layout

- Full RTL experience.
- Clean minimal interface.
- Light surfaces.
- Rounded cards.
- Clear hierarchy.
- Mobile-first design.

## Semantic Colors

- Primary Arvin blue/purple identity.
- Green for completion/success.
- Orange/yellow for waiting and attention.
- Red for important/danger actions.
- Soft category colors for organization.

# Required Screens

## Home

Contains:
- Header
- Search
- Statistics
- Time, projects, categories and labels shortcuts
- Task cards
- Today/future grouping
- Bottom navigation

## Quick Entry

Fast creation must support:

- Title input
- Project selection
- Category selection
- Label selection
- Date/time selection
- Quick save
- Expansion to full task

## Task Detail

Required:

- Title
- Context
- Status
- Reminder
- Labels
- Follow-up history
- Timeline
- Add follow-up
- Complete action

## Follow-up

Core feature:

- Follow-up records
- Dates
- Reminders
- History timeline
- New follow-up creation

## Notebook

Supports:

- Notes
- Checklists
- Personal/work separation
- Search
- Categories
- Editing

## Calendar

Supports:

- Persian calendar
- Day/week/month views
- Task integration
- Reminder visualization

# Navigation

Required areas:

- Home
- Calendar
- Notebook
- Next actions
- More

# Icons

Icons must be consistent, functional and semantically clear.

# Development Control

Before changing UI:

1. Compare with this document.
2. Check canonical contracts.
3. Resolve document conflicts.
4. Update reference only after approved decision.

# Production Goal

Arvin final release must reproduce the approved product experience with stable architecture, tested behavior and production quality.
