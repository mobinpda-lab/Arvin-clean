# دفترچه و فیلترهای Home — قرارداد مرجع محصول
> وضعیت: Binding Product Contract — ثبت‌شده بر اساس قرارداد مالک و تصاویر مرجع 2026-09-28
> مرجع اجرایی: Issue #1911 و PR/Issueهای مرتبط. این سند جایگزین کد یا تست نیست و باید با رفتار واقعی exact HEAD هم‌خوان شود.
## 1. تعریف دفترچه
- «یادداشت‌ها» در گفتگوهای آروین = «دفترچه».
- دفترچه یک بخش مستقل محصول است.
- Checklist یک بخش، تب، صفحه یا حالت مستقل در فهرست دفترچه نیست.
- قابلیت فعلی دفترچه باید حفظ شود و فقط ویرایش/اصلاح شود؛ بازنویسی یا ساخت دفترچه دوم مجاز نیست.
## 2. سه ابزار درون‌متن دفترچه
در پایین ویرایشگر دفترچه، سه دکمه اختصاصی مستقل و در یک ردیف قرار می‌گیرند:
1. شماره خودکار
2. تیک
3. چک‌لیست
رفتار هر سه:
- با یک ضربه فعال و با یک ضربه خاموش می‌شود.
- پس از فعال‌شدن، متن از محل فعلی با همان قالب ادامه پیدا می‌کند.
- با خاموش‌شدن، ادامه متن از همان نقطه به متن عادی برمی‌گردد.
- هیچ‌کدام صفحه/بخش مستقل ایجاد نمی‌کند.
- Undo/Redo، autosave، edit و reopen باید حفظ شوند.
- چک‌لیست صرفاً یک ابزار inline است و نباید از فهرست دفترچه به‌عنوان بخش جدا نمایش داده شود.
## 3. Taxonomy مشترک
Project، Category/Group و Tag در دفترچه دقیقاً همان موجودیت‌های محیط کار/Task هستند.
- Storage/Model/Repository موازی ممنوع.
- یک Project می‌تواند چند Category/Group و چند Note/Task داشته باشد.
- یک Category/Group می‌تواند چند Note و Task داشته باشد.
- یک Note یا Task می‌تواند چند Tag داشته باشد.
- یک Note/Task در صورت قرارداد UI می‌تواند چند Category/Group داشته باشد؛ در صورت محدودیت فعلی مدل، قبل از تغییر مدل باید وابستگی و migration بررسی و DeepSeek/Cross Review انجام شود.
- ایجاد و انتخاب دو عمل مستقل‌اند و مورد تازه باید بلافاصله قابل انتخاب باشد.
## 4. فهرست دفترچه
فهرست دفترچه باید فیلترهای مستقل و قابل ترکیب برای:
- Project
- Category/Group
- Tag
داشته باشد.
ظاهر کلی فهرست از تصویر مرجع ایده می‌گیرد: جستجو، فیلترهای واضح، کارت‌های خوانا، فضای سفید مناسب، RTL و رنگ‌بندی معنایی؛ تصویر مرجع جایگزین تست عملکردی نیست.
## 5. Home — چهار نمای فیلتر
### نمای زمان
- گروه‌بندی زمانی.
### نمای پروژه‌ها
- Roll Box انتخاب Project
- Roll Box انتخاب Category/Group
- نتیجه فقط Taskهای منطبق را نشان دهد.
### نمای دسته‌ها
- Roll Box انتخاب Category/Group
- نتیجه فقط Taskهای منطبق را نشان دهد.
### نمای برچسب‌ها
- Roll Box انتخاب Project
- Roll Box انتخاب Category/Group
- Roll Box انتخاب Tag
- نتیجه فقط Taskهای منطبق را نشان دهد.
فیلترها باید قابل ترکیب باشند، مقدار انتخاب‌شده واضح باشد، گزینه «همه» داشته باشند و تغییر فیلتر بدون بستن/بازکردن صفحه نتیجه را تازه کند.
## 6. رنگ و ظاهر
- چهار نمای Home باید از زبان رنگی مرجع پیروی کنند و تک‌رنگ نباشند.
- رنگ باید semantic باشد و صرفاً تزئینی نباشد.
- Project، Category، Tag و Time از رنگ‌های متمایز استفاده کنند.
- متن، وضعیت، disabled، selected و error باید کنتراست قابل‌قبول داشته باشند.
- رنگ تنها نشانه وضعیت نباشد؛ متن/آیکون/حالت نیز باید وضعیت را منتقل کند.
## 7. محافظت از قابلیت‌های موجود
قبل از هر تغییر در این حوزه:
- کد و تست قابلیت فعلی پیدا و audit شود.
- قابلیت موجود حذف یا با نسخه موازی جایگزین نشود.
- تغییر UI نباید persistence را بشکند.
- داده‌های قدیمی باید قابل بازیابی باشند.
- حذف تست فقط با جایگزین هم‌ارزش مجاز است.
- حذف Project/Category/Tag مورد استفاده نباید داده/رابطه را خراب کند؛ Archive/Disable یا rename امن باید ترجیح داده شود.
- هر تغییر Model/Storage/Migration نیازمند بازبینی معماری/DeepSeek است.
