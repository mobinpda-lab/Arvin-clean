# سند ایده محصول آروین — تحلیل نیازهای Time Jot

تاریخ ثبت: ۱۴۰۵/۰۵/۲۳

## 1. منبع ایده

این سند متن نیازمندی ارائه‌شده توسط کاربر برای ساخت یک نرم‌افزار پیگیری الکترونیکی کارها با الهام از تجربه Time Jot را به‌عنوان یکی از اسناد مرجع ایده و محصول آروین ثبت می‌کند.

هدف این سند کپی‌کردن یک برنامه دیگر نیست؛ هدف، ثبت نیازهای محصول، تصمیم‌های UX و تحلیل فاصله آن‌ها با وضعیت واقعی Arvin-clean است.

## 2. نیازهای محصول ثبت‌شده

- تاریخ هجری شمسی و ساعت سیستم با امکان ویرایش.
- ثبت یک کار و ثبت چندین پیگیری برای آن در طول زمان.
- مشاهده تاریخچه کامل پیگیری‌ها.
- دسته‌بندی و Tag.
- Reminder برای کار و پیگیری.
- PDF و اشتراک‌گذاری PDF برای یک کار همراه تاریخچه پیگیری‌ها.
- PDF و اشتراک‌گذاری فهرست کارها.
- Backup و Restore قابل انتقال به گوشی دیگر.
- بایگانی و سطل زباله.
- ویرایش در همه بخش‌ها، با نمایش عادی به‌صورت Read-only و ورود به Edit فقط با دکمه ویرایش.
- انتخاب چندتایی با Long Press و عملیات گروهی.
- Swipe چپ/راست با رفتار قابل تنظیم در Settings.
- توضیحات برای کار.
- نمایش آخرین پیگیری و ساعت/دقیقه در فهرست.
- جستجوی سراسری.
- FAB با علامت + در پایین صفحات.
- صفحه اصلی فهرست موارد و امکانات اصلی در منوی برنامه.
- مرتب‌سازی بر اساس تاریخ، آخرین ورودی و عنوان و امکان معکوس‌کردن ترتیب.
- یادداشت ساده که در صورت نیاز کاربر بتواند به مورد دارای پیگیری تبدیل شود.
- Checklist داخل یادداشت.
- نماهای امروز، آینده و عقب‌افتاده.
- ثبت خودکار اطلاعات در مراحل بازگشت/خروج.
- UI مدرن، فارسی و RTL.
- فونت اصلی پروژه: **IRANSans / IranSansX(Eco) طبق فایل فونت ارائه‌شده توسط کاربر**.

## 3. قرارداد Simple Note

Note ساده با Task دارای پیگیری یکی نیست.

رفتار مصوب:

1. مورد جدید می‌تواند ابتدا یک Note ساده باشد.
2. تاریخ و ساعت Note هنگام ایجاد از سیستم گرفته می‌شود.
3. تاریخ و ساعت Note قابل ویرایش است.
4. Note به‌صورت خودکار ذخیره می‌شود.
5. پس از خروج، Note Read-only است.
6. در مراجعه بعدی، کاربر با دکمه «ویرایش» آن را وارد حالت Edit می‌کند.
7. Note نباید صرفاً به دلیل داشتن تاریخ/ساعت، Reminder یا Calendar Event ایجاد کند.
8. تاریخ Note نباید به Google Calendar یا Calendar گوشی ارسال شود.
9. فعال‌کردن پیگیری برای یک مورد، قابلیت‌های Task/FollowUp را برای همان مورد فعال می‌کند.

## 4. تحلیل Reminder

Reminder باید از timestamp خود Note/Task جدا باشد.

- `createdAt` یا زمان ثبت، زمان وقوع ثبت رکورد است.
- `dateTime` مربوط به FollowUp، زمان پیگیری ثبت‌شده است و قابل ویرایش است.
- `nextFollowUp` زمان پیگیری بعدی است و مستقل از FollowUp فعلی است.
- Reminder زمان هشدار است و نباید با زمان ثبت یا زمان یادداشت اشتباه شود.

این تفکیک برای جلوگیری از ورود ناخواسته Noteها به Calendar و برای طراحی درست Reminder ضروری است.

## 5. مقایسه با وضعیت Arvin-clean

### موجود/تثبیت‌شده یا دارای پایه

- Flutter/Dart و Android.
- RTL/فارسی و تاریخ جلالی.
- Task، Tag، Archive و Trash پایه.
- Calendar جلالی و مسیر Reminder.
- FollowUp Domain/Application/Agenda در Waveهای مستقل.
- Simple Notebook Domain/Storage/Application/Session Policy در Waveهای مستقل.
- Backup/Restore پایه و فایل‌های مربوط به Cloud/Dropbox در پروژه وجود دارند.
- CI مستقل و Parallel Wave.
- مستندسازی تصمیم‌ها و جلوگیری از دوباره‌کاری.

### ناقص یا نیازمند تکمیل

- اتصال کامل FollowUp به UI اصلی و داده واقعی TaskRepository.
- UI نهایی Simple Notebook و Settings Toggle.
- Checklist برای Note.
- جستجوی سراسری واقعی.
- Sort کامل و Reverse Sort.
- PDF برای Task/FollowUp و فهرست کارها.
- Share خروجی‌ها.
- Font Settings و اعمال سراسری فونت.
- اتصال production-ready به Google Calendar برای Task/FollowUp.
- Dropbox Backup/Restore production-ready و Conflict handling.
- E2E regression برای مسیرهای اصلی.
- بازسازی کامل UI مرجع؛ CI سبز به‌تنهایی به معنی تکمیل UI نیست.

## 6. Guardrails

- مستندات هر تصمیم محصولی و هر تغییر مهم همراه توسعه به‌روزرسانی شوند.

## 8. تصمیم معماری محصول

آروین باید یک برنامه مدیریت کار و پیگیری واقعی باشد، نه Todo List ساده. هسته محصول:

`Task + FollowUp History + Simple Note + Calendar + Reminder + Tags + Archive + Trash + Backup + Settings`

اما مرزها باید روشن بمانند:

`Simple Note != Reminder != FollowUp != Calendar Event`

این مرزبندی از مهم‌ترین نتایج تحلیل این سند است.
