# Arvin Visual Design Canonical Contract

Status: Canonical UI reference

این سند مرجع طراحی رابط کاربری آروین است و تصاویر نصب واقعی برنامه، تصمیم‌های نهایی رابط و قابلیت‌های موجود پروژه را به یک قرارداد واحد تبدیل می‌کند.

## اصل حاکم

تصاویر مرجع، قرارداد چیدمان و تجربه کاربری هستند؛ نه داده ثابت. متن‌ها، شمارنده‌ها، وضعیت‌ها و محتوا باید از مدل‌های واقعی برنامه تولید شوند.

در تعارض، این سند و تصاویر نهایی نصب واقعی بر مستندات قدیمی UI اولویت دارند.

## ظاهر مشترک

- رابط فارسی و RTL.
- رنگ اصلی: #4A4CAB.
- فونت: VazirHarf v34.003.
- پس‌زمینه روشن.
- کارت‌های سفید با گوشه نرم و سایه ظریف.
- آیکون‌ها هماهنگ، ساده و قابل فهم.

## صفحه اصلی

ساختار نهایی:

- عنوان: بسم الله الرحمن الرحیم
- عنوان دوم: مدیریت کارها و پیگیری آروین
- اعلان سمت چپ، منو سمت راست.
- جست‌وجوی گرد زیر عنوان.

چهار کارت آماری قدیمی خانه حذف می‌شوند.

چهار ورودی اصلی خانه:

1. زمان: آیکون تقویم نارنجی
2. پروژه‌ها: آیکون پوشه آبی
3. دسته‌ها: آیکون شبکه بنفش
4. برچسب‌ها: آیکون تگ سبزآبی

ترتیب RTL در تمام نماها ثابت است.

## گروه‌بندی واقعی

### زمان

کارها بر اساس موعد انجام:
- عقب‌افتاده
- امروز
- آینده
- بدون موعد

پیگیری و یادآوری جایگزین موعد انجام نیستند.

### پروژه‌ها

نمایش کار زیر پروژه، گروه بدون پروژه، ایجاد و ویرایش پروژه و افزودن کار از همان گروه.

### دسته‌ها

گروه‌بندی مستقل از پروژه، انتخاب رنگ و آیکون، گروه بدون دسته.

### برچسب‌ها

هر کار چند برچسب می‌تواند داشته باشد و نمایش چندگروهی نباید باعث تکثیر داده شود.

## کارت کار

کارت شامل:
- کنترل انجام
- عنوان برجسته
- پروژه/دسته
- موعد
- وضعیت واقعی
- آخرین پیگیری یا خلاصه توضیحات

لمس کارت باید جزئیات را باز کند، نه ویرایش مستقیم.

## ناوبری پایین

پنج مقصد ثابت:

خانه | تقویم | دفترچه | اقدام بعدی | بیشتر

پروژه و دسته تب جداگانه نیستند.

## ورود سریع

ورودی سریع پنل پایین صفحه است.

الزامات:
- ثبت پیاپی بدون بسته شدن پنل.
- پاک شدن فقط عنوان و توضیحات بعد از ثبت موفق.
- حفظ انتخاب‌های پروژه، دسته، برچسب، موعد، یادآوری و تکرار.
- جلوگیری از ثبت تکراری.
- حفاظت از پیش‌نویس هنگام خروج.

## کار پیگیری‌دار

جزئیات شامل:
- مشخصات کار
- آخرین پیگیری
- تاریخچه پیگیری‌ها
- افزودن پیگیری
- ویرایش
- انجام کار

ثبت پیگیری باید به تاریخچه اضافه شود و جایگزین آن نشود.

## دفترچه

دو حالت مستقل:

- یادداشت ساده
- چک‌لیست

ویرایشگر یادداشت تمام صفحه و محتوامحور است.

## تقویم و اقدام بعدی

تقویم شمسی واقعی و متصل به داده اصلی.

کار، پیگیری، یادآور و رویداد رسمی باید از هم جدا باشند.

## جلوگیری از بازگشت طراحی قدیمی

موارد ممنوع:

- چهار کارت آماری قدیمی خانه.
- داده ساختگی برای تطبیق ظاهری.
- صفحات موازی با ذخیره‌سازی جدا.
- دکمه‌ها و تنظیمات بدون عملکرد.

## معیار پذیرش

خروجی نهایی باید اپلیکیشن واقعی باشد و روی اندروید تست شود.

مراحل تحویل:
1. قراردادها و مستندات.
2. خانه و گروه‌بندی.
3. ورود سریع و فرم کامل.
4. جزئیات و پیگیری.
5. دفترچه.
6. تقویم و تنظیمات.
7. تست یکپارچه و شواهد اجرا.
