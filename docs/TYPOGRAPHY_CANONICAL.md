# قرارداد مرجع تایپوگرافی آروین

- وضعیت: **تصمیم قطعی مالک محصول، الزام‌آور برای تمام رابط کاربری**
- تاریخ ثبت: ۱۴۰۵/۰۸/۰۳
- مرجع پذیرش: Issue #2974
- مرجع فنی یگانه: این سند
- تقدم: این سند بر هر سند قدیمی، تست، کامنت، PR یا پیش‌فرض پیاده‌سازی متعارض مقدم است.

## 1. خانوادهٔ رسمی

خانوادهٔ سراسری و اجباری UI آروین **Vazirmatn** است. VazirHarf مجاز نیست پیش‌فرض، جایگزین خودکار یا fallback UI باشد. فونت دستگاه/سیستم نیز نباید در مسیر پیش‌فرض به‌صورت بی‌صدا جایگزین Vazirmatn شود. گزینهٔ غیرفعال یا صوری Vazirmatn در تنظیمات قابل قبول نیست.

## 2. نگاشت قطعی نقش‌ها

| نقش رابط کاربری | وزن | Flutter |
|---|---|---|
| متن اصلی و محتوای معمول | Regular 400 | `FontWeight.w400` |
| توضیحات فرعی، راهنما و metadata | Light 300 | `FontWeight.w300` |
| منوها، کنترل‌ها و دکمه‌ها | Medium 500 | `FontWeight.w500` |
| تیترها و عنوان بخش‌ها | Bold 700 | `FontWeight.w700` |
| تأکیدهای مهم و وضعیت‌ها | SemiBold 600 | `FontWeight.w600` |

وزن‌های خانواده: Thin 100، ExtraLight 200، Light 300، Regular 400، Medium 500، SemiBold 600، Bold 700، ExtraBold 800 و Black 900. هر فایل باید با وزن واقعی متناظر خود ثبت شود؛ استفاده از Regular به‌جای Light یا SemiBold ممنوع است. لازم نیست هر ۹ وزن در هر صفحه مصرف شود.

اندازه، رنگ، فاصله، ارتفاع خط و سلسله‌مراتب موجود خارج از این تغییر باقی می‌مانند، مگر آنکه تصمیم محصولی جداگانه‌ای وجود داشته باشد.

## 3. منبع، مجوز و provenance

منبع مورد تأیید: مخزن رسمی `rastikerdar/vazirmatn`، snapshot:
`6e553e33489a8f9dfaccc76860a2e3f3c1e66de7`

مسیرهای مورد انتظار:
`misc/UI-Farsi-Digits/fonts/ttf/Vazirmatn-UI-FD-{Thin,ExtraLight,Light,Regular,Medium,SemiBold,Bold,ExtraBold,Black}.ttf`

مجوز رسمی `OFL.txt` باید همراه دارایی‌ها نگهداری شود. برای هر فایل، مسیر منبع، نام وزن، اندازه و SHA-256 واقعی باید در manifest ثبت شود. hash نباید حدس زده شود.

## 4. قرارداد Flutter

- نام خانوادهٔ ثبت‌شده در Flutter دقیقاً `Vazirmatn` است.
- هر ۹ وزن باید به‌عنوان فایل متناظر و مستقل در مخزن موجود باشد و `pubspec.yaml` همان فایل‌ها را با وزن صحیح ثبت کند.
- ThemeData روشن و تیره و تمام صفحات، dialogها، bottom sheetها، navigation، فرم‌ها، کارت‌ها و تنظیمات باید از یک مرجع تایپوگرافی استفاده کنند.
- TextTheme پایه باید نگاشت پنج‌نقشی بالا را پیاده کند. TextStyleهای مستقیم فقط با همان نقش معنایی سازگارند.
- Settings، SharedPreferences و Backup/Restore نباید خانواده یا fallback موازی ایجاد کنند.
- مقدار خالی/غایب، مقدار ناشناخته و مقدار legacy برابر `VazirHarf` باید بدون خطا به `vazirmatn` مهاجرت داده شوند. Restore قدیمی نباید شکست بخورد.
- PDF و گزارش خروجی سطحی جدا هستند. هر استثنا باید صریحاً مستند و با آزمون embedding و رندر تأیید شود و مجوز تغییر UI نیست.

## 5. ممنوعیت‌ها

1. VazirHarf به‌عنوان پیش‌فرض یا fallback UI.
2. فونت سیستم/دستگاه به‌عنوان جایگزین خاموش Vazirmatn در مسیر پیش‌فرض.
3. معرفی Vazirmatn به‌عنوان گزینهٔ غیرفعال یا غیرمحلی.
4. معرفی خانوادهٔ کامل پیش از وجود و بررسی هر ۹ فایل، مجوز، provenance و بسته‌بندی.
5. نگه‌داشتن اسناد فعال متعارض.
6. تغییر مستقیم `main` یا اعلام پذیرش بدون شواهد exact-SHA.

## 6. گیت‌های پذیرش

- جست‌وجوی کل مخزن برای خانواده‌ها، وزن‌ها، fallback، Settings و PDF؛ طبقه‌بندی نتایج به فعال، تاریخی/منسوخ یا غیرمرتبط.
- تطبیق فایل‌های واقعی، مجوز، provenance، SHA-256، manifest، `pubspec.yaml` و بسته‌بندی APK.
- آزمون قراردادی برای خانوادهٔ پیش‌فرض، هر ۹ وزن، نگاشت پنج نقش، تم روشن/تیره، Settings و سازگاری Backup/Restore.
- `flutter analyze`، تست‌های متمرکز، کل تست‌ها و Debug/Release build روی SHA دقیق نامزد.
- Device Smoke و بررسی بصری فارسی/RTL، ارقام، تاریخ‌ها، متن طولانی و viewport باریک و عادی.
- CI موفق به‌تنهایی اثبات ظاهر نهایی یا اجرای دستگاه فیزیکی نیست.

تا عبور از تمام گیت‌ها، قرارداد از نظر محصول قطعی است اما پیاده‌سازی کامل و آمادگی انتشار **تأییدشده محسوب نمی‌شود**.

## 7. ثبت baseline

در baseline ثبت‌شده برای Issue #2974، فایل‌های مسیر `assets/fonts/ui/vazirmatn/` شامل فقط Regular، Medium و Bold بوده‌اند و خانوادهٔ کامل ۹ وزن را تشکیل نمی‌داده‌اند. این شرح وضعیت اولیه است، نه ادعای تکمیل. هر پیشرفت باید با commit/SHA، فایل‌های واقعی و نتایج آزمون در Issue #2974 ثبت شود.
