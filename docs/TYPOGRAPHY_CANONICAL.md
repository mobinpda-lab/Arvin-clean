# قرارداد مرجع تایپوگرافی آروین

**وضعیت:** تصمیم قطعی مالک محصول، الزام‌آور برای تمام رابط کاربری آروین  
**ثبت:** 2026-10-24  
**مبنای ثبت در GitHub:** Issue #2974  
**مرجع:** این سند بر هر سند قدیمی، تست، کامنت، PR یا پیش‌فرض پیاده‌سازی که با آن تعارض دارد مقدم است.

## 1. خانوادهٔ فونت

فونت سراسری رابط کاربری آروین **Vazirmatn (وزیرمتن)** است. VazirHarf دیگر فونت پیش‌فرض، جایگزین خودکار یا fallback رابط کاربری نیست. انتخاب فونت دستگاه نیز نباید در مسیر پیش‌فرض، وزیرمتن را بی‌صدا با خانواده‌ای دیگر جایگزین کند.

## 2. نگاشت الزامی وزن‌ها

| نقش | وزن فونت | Flutter |
|---|---|---|
| متن اصلی و محتوای معمول | Regular 400 | `FontWeight.w400` |
| توضیحات فرعی، راهنما و metadata | Light 300 | `FontWeight.w300` |
| منوها، کنترل‌ها و دکمه‌ها | Medium 500 | `FontWeight.w500` |
| تیترها و عنوان بخش‌ها | Bold 700 | `FontWeight.w700` |
| تأکیدهای مهم داخل متن یا وضعیت | SemiBold 600 | `FontWeight.w600` |

این نگاشت یک قرارداد نقش‌محور است، نه صرفاً فهرستی از وزن‌های قابل‌انتخاب. برای یک عنصر، وزن باید از نقش معنایی آن تعیین شود؛ از وزن‌های دلخواه یا وزن‌های دیگر به‌عنوان تزئین استفاده نشود. اندازه، رنگ، فاصله، ارتفاع خط و سلسله‌مراتب فعلی بدون نیاز محصولی تغییر نکنند.

## 3. قرارداد فنی

- خانوادهٔ ثبت‌شده در Flutter: `Vazirmatn`.
- پنج فایل واقعی وزن‌های 300، 400، 500، 600 و 700 باید در APK بسته‌بندی شوند و از منبع رسمی دارای مجوز و provenance قابل‌ردیابی باشند.
- هر وزن در `pubspec.yaml` با فایل متناظر خودش ثبت شود؛ فایل Regular نباید به‌عنوان Light یا SemiBold جا زده شود.
- `ThemeData` روشن و تیره، همهٔ صفحات، dialogها، bottom sheetها، navigation، فرم‌ها، کارت‌ها و تنظیمات باید از یک مرجع تایپوگرافی استفاده کنند.
- نقش‌های پایهٔ `TextTheme` باید با جدول بالا هم‌راستا شوند. استفادهٔ مستقیم از `TextStyle` یا `FontWeight.w*` فقط وقتی مجاز است که با نقش این قرارداد سازگار باشد.
- Settings، مقدارهای ذخیره‌شده و Backup/Restore نباید خانواده‌ای موازی یا fallback پنهان بسازند. مقدارهای قدیمی `VazirHarf` باید با migration سازگار و صریح به قرارداد جدید نگاشت شوند؛ restore قدیمی نباید به‌علت مقدار قدیمی فونت شکست بخورد.
- PDF و گزارش‌های خروجی سطحی جدا از UI هستند. اگر به‌دلیل خوانایی/چاپ خانواده یا وزن متفاوتی دارند، آن استثنا باید صریحاً در قرارداد PDF مستند و با آزمون embedding و رندر بررسی شود؛ این استثنا مجوز تغییر فونت UI نیست.
- فارسی و RTL، اعداد و تاریخ‌های محصول، متن‌های طولانی و viewport باریک باید در بازبینی بصری پوشش داده شوند.

## 4. منع‌های صریح

- ممنوع: VazirHarf به‌عنوان فونت پیش‌فرض یا fallback رابط کاربری.
- ممنوع: معرفی Vazirmatn به‌عنوان گزینهٔ غیرفعال درحالی‌که تصمیم محصول آن را فونت اصلی می‌داند.
- ممنوع: نشان‌دادن تکمیل کار بدون وجود هر پنج فایل واقعی و بررسی بسته‌بندی آن‌ها.
- ممنوع: نگه‌داشتن دو قرارداد متعارض در اسناد فعال. اسناد قدیمی فقط می‌توانند به‌عنوان تاریخچه باقی بمانند و باید برچسب «منسوخ؛ مرجع جاری: `docs/TYPOGRAPHY_CANONICAL.md`» داشته باشند.
- ممنوع: تغییر مستقیم `main` یا ادعای پذیرش بدون شواهد exact-SHA.

## 5. گیت پذیرش

1. جست‌وجوی کل مخزن برای خانواده‌ها، وزن‌ها، fallbackها، Settings و PDF انجام شود و هر نتیجه به «فعال»، «تاریخی/منسوخ» یا «غیرمرتبط» طبقه‌بندی شود.
2. فایل‌های فونت و مجوز/منبع آن‌ها بررسی شوند؛ manifest وزن‌ها و بسته‌بندی APK باید با فایل‌های واقعی تطبیق داشته باشد.
3. آزمون‌های قراردادی default family، پنج وزن، نقش‌های UI، روشن/تیره، Settings و backup compatibility را اثبات کنند.
4. `flutter analyze`، تست‌های متمرکز، کل تست‌ها و Debug/Release build روی SHA دقیق نامزد اجرا شوند.
5. Device Smoke و بررسی بصری فارسی/RTL در viewport باریک و عادی انجام شود. اجرای موفق CI به‌تنهایی تأیید نهایی ظاهر یا دستگاه فیزیکی نیست.
6. تا پایان این گیت‌ها، اجرای کامل قرارداد و آماده‌بودن انتشار تأییدشده محسوب نمی‌شود.
