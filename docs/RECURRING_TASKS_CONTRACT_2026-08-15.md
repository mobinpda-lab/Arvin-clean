# Arvin — Recurring Tasks Contract 2026-08-15

## هدف
ثبت قابلیت کارهای پرتکرار بدون ایجاد مدل یا storage موازی و با حفظ Unified Item.

## الگوهای تکرار
- روزانه
- ماهانه
- سالانه
- یک‌بار در روز
- فاصله قابل تنظیم در صورت پشتیبانی مدل نهایی (مثلاً هر N روز/ماه)

## زمان
- ساعت برای کار اجباری نیست.
- کار تکرارشونده می‌تواند timed یا all-day باشد.
- برای all-day هیچ ساعت مصنوعی در persistence/UI ساخته نمی‌شود.

## Resume From Today
اگر یک کار تکرارشونده از موعد گذشته باشد، کاربر می‌تواند با یک اقدام سریع «از امروز ادامه بده» را انتخاب کند.

این اقدام فقط برنامه آینده را از امروز محاسبه می‌کند و نباید تاریخچه، completionهای قبلی یا داده‌های گذشته را تخریب کند.

## اقدامات سریع پیشنهادی
- از امروز ادامه بده
- ادامه از تاریخ انتخابی
- رد کردن نوبت فعلی
- ویرایش الگوی تکرار

## معماری
- Recurrence باید روی همان Unified Item/Task قرار بگیرد.
- Reminder، FollowUp و Recurring Task نباید storage یا repository موازی بسازند.
- تبدیل Reminder به Item باید با همین قرارداد سازگار باشد.

## UI
- کارت تکرارشونده باید ساده و خلوت باشد.
- زمان، در صورت وجود، اطلاعات ثانویه است و در کنار عنوان نوع مورد نمایش داده می‌شود.
- حالت all-day بدون ساعت نمایش داده می‌شود.
- UI باید با اصل طراحی آروین هماهنگ باشد: الهام از سادگی و سلسله‌مراتب UI ChatGPT، بدون کپی مستقیم.

## Definition of Done
Domain/model، persistence، UI واقعی، تست recurrence و all-day، regression، CI سبز و مستندات به‌روز باید همگی تکمیل شوند.
