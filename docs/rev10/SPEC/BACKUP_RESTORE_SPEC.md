# Backup / Restore Specification
Reuse ArvinBackupManager and ArvinBackupService; no parallel format or persistence. Backup includes accepted entities/edges with stable IDs and optional-field semantics. Encrypted backup requires non-empty matching confirmation; wrong passphrase/tamper fails closed without mutation. Restore from independent Database A into Database B; repeated restore is idempotent. Preserve destination-only records and rollback after injected mid-restore failure. Verify SQLite integrity/FKs, IDs, explicit NULL/absent fields, tags, people, follow-ups, reminders and relationships after close/reopen. SQLCipher is not approved; assess compatibility, keys, recovery and migration before adoption.
