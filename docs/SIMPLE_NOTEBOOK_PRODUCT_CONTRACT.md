# قرارداد محصول — دفترچه یادداشت ساده

این سند سابقه تصمیم محصولی دفترچه یادداشت ساده آروین است و باید قبل از هر تغییر مرتبط با Note بررسی شود.

## رفتار ثبت

- کاربر موضوع و متن یادداشت را وارد می‌کند.
- تاریخ و ساعت هنگام ایجاد، به‌صورت خودکار از زمان سیستم وارد می‌شود.
- تاریخ و ساعت پیش‌فرض توسط کاربر قابل ویرایش هستند.
- پس از ورود/ویرایش، ذخیره‌سازی باید خودکار باشد.

## رفتار پس از خروج

- خروج از صفحه، یادداشت را در حالت فقط‌خواندنی نمایش می‌دهد.
- در مراجعه بعدی، کاربر با دکمه «ویرایش یادداشت» آن را وارد حالت ویرایش می‌کند.
- فعال/غیرفعال بودن قابلیت دفترچه و رفتار ویرایش باید در Settings قابل کنترل باشد.

## زمان یادداشت و Calendar

`dateTime` یادداشت فقط زمان مربوط به خود Note است.

- Note نباید به `CalendarReminder` تبدیل شود.
- Note نباید در Google Calendar ثبت شود.
- Note نباید در تقویم سیستم/گوشی ایجاد شود.
- تاریخ و ساعت Note فقط داخل داده‌های آروین نگهداری می‌شوند.
- نمایش Note در Calendar آروین نیز بدون تصمیم محصولی صریح مجاز نیست.

## معماری و سازگاری

- Note باید از Task/FollowUp مستقل بماند.
- Storage مستقل Note از کلید `arvin.simple_notes` استفاده می‌کند.
- Backup/Restore آینده باید Note را حفظ کند، بدون ایجاد Calendar Event.
- Calendar فعلی فقط در صورت regression یا نیاز صریح محصول تغییر می‌کند.

## منابع مرجع

تجربه `arvin-task-tracker` برای UX تاریخ/ساعت و رفتار یادداشت بررسی می‌شود و تجربه `daftar-peygiri` برای الگوهای محصول/CI به‌عنوان مرجع استفاده می‌شود؛ هیچ‌کدام جایگزین Source of Truth یعنی `Arvin-clean` نیستند.

## قانون ضد دوباره‌کاری

قبل از هر Commit مرتبط با Note:

1. وضعیت `main` بررسی شود.
2. PRهای باز و تغییرات قبلی Note بررسی شوند.
3. مدل و Storage موجود بررسی شوند.
4. Calendar/Backup compatibility بررسی شود.
5. فقط تغییر ضروری ایجاد شود.
6. تست مستقل اضافه یا به‌روزرسانی شود.
7. Commit و Workflowهای مستقل تا حد امکان موازی اجرا شوند.
