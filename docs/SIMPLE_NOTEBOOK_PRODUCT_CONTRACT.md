# قرارداد محصول — دفترچه یادداشت ساده

> **وضعیت:** این سند به‌عنوان سابقه تصمیمات Notebook حفظ شده است، اما برای مدل رابطه Note/Task/FollowUp توسط `docs/ITEM_NOTE_FOLLOWUP_PRODUCT_CONTRACT.md` superseded شده است. جزئیات زیر درباره رفتار Notebook همچنان معتبرند.

## رفتار ثبت

- کاربر موضوع و متن یادداشت را وارد می‌کند.
- تاریخ و ساعت هنگام ایجاد، به‌صورت خودکار از زمان سیستم وارد می‌شود.
- تاریخ و ساعت پیش‌فرض توسط کاربر قابل ویرایش هستند.
- پس از ورود/ویرایش، ذخیره‌سازی باید خودکار باشد.

## رفتار پس از خروج

- خروج از صفحه، یادداشت را در حالت فقط‌خواندنی نمایش می‌دهد.
- در مراجعه بعدی، کاربر با دکمه «ویرایش یادداشت» آن را وارد حالت ویرایش می‌کند.
- فعال/غیرفعال بودن قابلیت دفترچه و رفتار ویرایش باید در Settings قابل کنترل باشد.

## زمان یادداشت و Calendar

`dateTime` یادداشت فقط زمان مربوط به خود Note است و Reminder محسوب نمی‌شود.

- Note نباید به `CalendarReminder` تبدیل شود.
- Note نباید در Google Calendar ثبت شود.
- Note نباید در تقویم سیستم/گوشی ایجاد شود.
- تاریخ و ساعت Note فقط داخل داده‌های آروین نگهداری می‌شوند.
- نمایش Note در Calendar آروین نیز بدون تصمیم محصولی صریح مجاز نیست.

## مدل جدید

- یک مورد جدید ابتدا به‌صورت یادداشت ساده است.
- فعال‌کردن FollowUp همان مورد را به مورد پیگیری‌دار تبدیل می‌کند.
- داده‌ها و شناسه پایه نباید کپی شوند.
- Noteهای بدون FollowUp و موارد دارای FollowUp می‌توانند در UI جدا فیلتر شوند، ولی مسیر داده مستقل برای یک مورد ساخته نشود.
- جزئیات کامل در `docs/ITEM_NOTE_FOLLOWUP_PRODUCT_CONTRACT.md` است.

## منابع مرجع

تجربه `arvin-task-tracker` برای UX تاریخ/ساعت و رفتار تقویم بررسی می‌شود و تجربه `daftar-peygiri` برای الگوهای محصول/CI به‌عنوان مرجع استفاده می‌شود؛ هیچ‌کدام جایگزین Source of Truth یعنی `Arvin-clean` نیستند.

## قانون ضد دوباره‌کاری

قبل از هر Commit مرتبط با Note:

1. وضعیت `main` بررسی شود.
2. PRهای باز و تغییرات قبلی Note بررسی شوند.
3. مدل و Storage موجود بررسی شوند.
4. Calendar/Backup compatibility بررسی شود.
5. قرارداد مشترک Item/Note/FollowUp بررسی شود.
6. فقط تغییر ضروری ایجاد شود.
7. تست مستقل اضافه یا به‌روزرسانی شود.
8. Commit و Workflowهای مستقل تا حد امکان موازی اجرا شوند.
