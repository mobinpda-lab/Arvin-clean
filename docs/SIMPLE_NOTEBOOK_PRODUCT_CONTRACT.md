# قرارداد محصول — دفترچه یادداشت ساده

## وضعیت قرارداد
این فایل یک تصمیم قدیمی درباره Storage مستقل Note داشت. آن بخش با معماری جدیدتر پروژه ناسازگار بود و اکنون صریحاً **لغو/جایگزین** شده است.

مرجع فعال معماری `docs/ARVIN_PROJECT_OPERATING_PACKAGE.md` v49.0 و مسیر مهاجرت Unified Item است.

## معماری فعلی و لازم‌الاجرا
- Note یک قابلیت/حالت روی همان **Unified Item/Task** است؛ مدل دامنه مستقل و موازی ساخته نمی‌شود.
- Storage مستقل `arvin.simple_notes` ایجاد نمی‌شود.
- مسیر اصلی داده همان `arvin.tasks` و Boundaryهای canonical موجود است، مگر اینکه یک Migration رسمی و تست‌شده در آینده این قرارداد را تغییر دهد.
- Note، Reminder و FollowUp باید روی foundation مشترک همگرا بمانند و نباید Repository/Database موازی ایجاد کنند.

## رفتار ثبت
- کاربر موضوع و متن یادداشت را وارد می‌کند.
- تاریخ و ساعت ایجاد به‌صورت خودکار از زمان سیستم ثبت می‌شود و در صورت پشتیبانی UI قابل ویرایش است.
- ذخیره‌سازی/Auto-save باید از همان مسیر canonical Item انجام شود.
- Checklist نیز در صورت فعال‌شدن روی همان Item موجود ذخیره می‌شود.

## رفتار پس از خروج
- خروج از صفحه می‌تواند یادداشت را در حالت فقط‌خواندنی نشان دهد.
- ورود دوباره به حالت ویرایش با اقدام صریح «ویرایش یادداشت» انجام می‌شود.
- تنظیمات مربوط به تجربه Notebook نباید منبع داده دوم ایجاد کند.

## زمان Note و Calendar
زمان Note metadata داخلی همان Item است و به‌خودی‌خود Reminder یا Calendar Event نیست.

- Note نباید صرفاً به‌خاطر داشتن تاریخ/ساعت به `CalendarReminder` تبدیل شود.
- Note نباید بدون تصمیم/اقدام محصولی صریح در Google Calendar یا تقویم سیستم ثبت شود.
- Reminder یک مفهوم مستقل است و فقط از مسیر Reminder موجود ایجاد/زمان‌بندی می‌شود.
- هیچ ساعت ساختگی برای حالت بدون ساعت تولید نمی‌شود.

## Backup/Restore
Backup/Restore باید Note/Checklist و تمام فیلدهای canonical Item را در همان envelope موجود حفظ کند. راه‌حل Backup نباید Storage Note موازی ایجاد کند.

## قانون ضد دوباره‌کاری
قبل از هر تغییر Notebook:
1. `main`، PRهای باز و CI دقیق بررسی شوند.
2. `Task`/Unified Item، migration writer/reader و persistence موجود بررسی شوند.
3. قابلیت موجود دوباره ساخته نشود.
4. کوچک‌ترین تغییر قابل برگشت انتخاب شود.
5. تست focused + regression + CI/APK متناسب اجرا شود.
6. مستندات current-state/handoff همزمان به‌روز شوند.

## سابقه
تصمیم تاریخی «Note مستقل + `arvin.simple_notes`» برای حفظ ردپا در Git history باقی می‌ماند، اما از این نسخه به بعد قرارداد اجرایی نیست و نباید مبنای implementation جدید قرار گیرد.
