# Arvin v1 - Reporting Standard

## هدف
گزارش‌های پروژه باید برای مدیر پروژه و افراد غیر برنامه‌نویس قابل فهم باشند.

## قانون گزارش‌دهی
تمرکز گزارش روی پیشرفت محصول است، نه جزئیات پیچیده فنی.

## ساختار استاندارد گزارش

### 1- الان کجای پروژه هستیم؟
توضیح ساده مرحله فعلی پروژه.

### 2- چه کاری انجام شده؟
توضیح نتیجه کار و دلیل انجام آن.

### 3- وضعیت پروژه
نمایش بخش‌های:
- انجام شده
- در حال انجام
- باقی مانده

### 4- مرحله بعد
توضیح قدم بعدی به زبان ساده.

## اصول ثابت
- ظاهر و طراحی مرجع آروین بدون تصمیم رسمی تغییر نمی‌کند.
- گزارش‌ها کوتاه، واضح و قابل پیگیری باشند.
- هر تغییر مهم باید با مسیر استاندارد پروژه هماهنگ شود.

## پایان استاندارد گزارش
