# استاندارد گزارش‌دهی آروین — REV10

## هدف
گزارش برای مالک محصول و فرد غیر برنامه‌نویس ساده، روشن و قابل تصمیم‌گیری باشد؛ اما هیچ واقعیتی بدون مدرک اعلام نشود.

## قالب ثابت
- وضعیت فعلی: اکنون دقیقاً کجا هستیم؟
- انجام‌شده: چه چیزی واقعاً تغییر کرده یا اجرا شده است؟
- نتیجه: موفق، ناموفق، در صف یا نامشخص.
- مدرک: SHA، PR، Run، Job، فایل یا Artifact قابل بررسی.
- مانع: چه چیزی جلوی پذیرش را گرفته است؟
- قدم بعد: کوچک‌ترین اقدام مشخص و قابل بازگشت.

## قواعد قطعی
- وضعیت واقعی GitHub از روی ref، PR، Commit، Workflow و Job زنده خوانده شود؛ SHA تاریخی HEAD فرض نشود.
- هر نتیجه به Exact SHA خودش متصل است؛ PASS از SHA قبلی به SHA جدید منتقل نمی‌شود.
- وضعیت کد، نتیجه آزمون، پذیرش محصول و مجوز انتشار چهار موضوع جدا هستند.
- «پیاده‌سازی شده» به معنی «تأیید شده» نیست.
- Digest بسته Artifact با SHA256 فایل داخل بسته یکسان فرض نشود.
- اگر مدرک کافی وجود ندارد، «نامشخص» یا NOT VERIFIED نوشته شود.
- علت شکست یا توقف فقط با Log و شواهد واقعی اعلام شود؛ حدس درباره Runner، سرویس یا ریشه خطا ممنوع است.
- تست معتبر حذف، Skip یا تضعیف نشود. تست قدیمی فقط با حفظ هدف رفتاری و اثبات تغییر قرارداد اصلاح شود.
- واقعیت، تحلیل، تصمیم، برنامه و پیشنهاد از هم جدا نوشته شوند.
- گزارش فنی فقط به اندازه‌ای باشد که تصمیم و خطر را روشن کند.
- تاریخ و ساعت در صورت نیاز با تاریخ شمسی و ساعت ایران (Asia/Tehran) ثبت شوند؛ زمان UTC منبع اصلی GitHub نیز حفظ شود.
- از درصد پیشرفت، زمان باقی‌مانده و ادعای تکمیل بدون معیار قابل سنجش استفاده نشود.
- گزارش‌های اجرایی در یک بلوک قابل کپی ارائه شوند و از فاصله‌های خالی غیرضروری پرهیز کنند.

## وضعیت‌های مجاز
- SUCCESS / PASS: آزمون یا Job واقعاً موفق شده و دامنه آن مشخص است.
- FAILURE: آزمون یا Job واقعاً شکست خورده است.
- QUEUED: هنوز اجرا نشده؛ علت صف فقط با شواهد بیان می‌شود.
- IN_PROGRESS: اجرا ادامه دارد.
- PARTIAL: بخشی از قرارداد پوشش داده شده است.
- NOT VERIFIED / نامشخص: مدرک کافی برای پذیرش وجود ندارد.
- BLOCKED: مانع یا مجوز لازم وجود دارد.

## حکم محصول و انتشار
PRODUCT ACCEPTED فقط وقتی اعلام می‌شود که تمام گیت‌های لازم روی یک Exact Acceptance SHA موفق باشند و مالک محصول پذیرش کند. RELEASE GO فقط با مجوز صریح مالک و رفع همه موانع حاکمیتی و فنی مجاز است. Main، Merge، Release، Deployment و Production Migration بدون مجوز صریح ممنوع‌اند.

## ادامه کار
عبارت ادامه در گزارش‌های آروین: «ادامه آروین» است. این عبارت باید با ممیزی زنده GitHub و ادامه اقدام مجاز همراه باشد؛ نه با فرض‌کردن وضعیت گزارش قبلی.
