# Arvin — محصول: قرارداد تثبیت‌شده دفترچه، یادداشت، چک‌لیست و Home
## واژه‌شناسی قطعی
- هرجا در گفتگو «یادداشت‌ها» گفته می‌شود، منظور همان بخش «دفترچه» است.
- «چک‌لیست» بخش یا تب مستقل در دفترچه نیست؛ ابزار درون ویرایشگر دفترچه است.
## دفترچه / یادداشت
- دفترچه یک بخش مستقل در آروین است.
- پروژه، دسته و برچسب دفترچه همان داده‌های canonical محیط کار/کارها هستند؛ هیچ فهرست، مخزن یا مدل موازی برای دفترچه ساخته نشود.
- یک پروژه می‌تواند چند دسته، چند کار و چند یادداشت داشته باشد.
- هر کار و هر یادداشت می‌تواند چند برچسب داشته باشد.
- هر دسته می‌تواند چند یادداشت و چند کار داشته باشد.
- فیلتر فهرست دفترچه باید بر اساس پروژه، دسته و برچسب در دسترس باشد و از همان داده‌های canonical استفاده کند.
- ظاهر دفترچه از تصویر مرجع پیوست‌شده این گفتگو ایده می‌گیرد: ساده، خوانا، RTL، کارت‌های مرتب و ویرایشگر تمیز؛ اما رفتار داده‌ای canonical باقی می‌ماند.
## ابزارهای درون ویرایشگر دفترچه
- شماره‌گذاری خودکار، تیک و چک‌لیست سه ابزار مجزای پایین ویرایشگر هستند و در یک ردیف کنار هم قرار می‌گیرند.
- با فعال‌کردن هر ابزار، قالب از محل مکان‌نما به بعد ادامه پیدا می‌کند.
- با خاموش‌کردن ابزار، ادامه متن به متن عادی برمی‌گردد.
- چک‌لیست یک بخش مستقل، تب مستقل یا لیست مستقل در دفترچه نیست.
- داده‌های قدیمی چک‌لیست که قبلاً در canonical storage وجود دارند نباید حذف شوند؛ هر تغییر جدید باید backward-compatible باشد و بدون مهاجرت تأییدنشده داده قدیمی را دور نریزد.
## فرم ویرایش کار
- چک‌لیست یک قابلیت داخلی فرم ویرایش کار است و باید با یک کلیک فعال/غیرفعال شود.
- «تکرار» و «اولویت» در یک ردیف قرار بگیرند.
- هرجا در فرم ویرایش کار تاریخ و ساعت مربوط به یک مورد هستند، تاریخ و ساعت کنار هم در یک ردیف باشند؛ از جمله موعد، یادآور و پیگیری.
- تاریخ و ساعت باید RTL و با رقم فارسی نمایش داده شوند.
## Home — چهار کارت اصلی و فیلترها
- چهار کارت اصلی «زمان / پروژه‌ها / دسته‌ها / برچسب‌ها» باید از نظر ظاهری نزدیک به تصویر مرجع باشند: کارت‌های رنگی، آیکون واضح، نوشته کامل و خوانا، بدون ellipsis ناخواسته یا بریده‌شدن عنوان.
- در Home، انتخاب «پروژه‌ها» فیلتر رول‌باکس پروژه + دسته را نشان می‌دهد.
- انتخاب «دسته‌ها» فیلتر رول‌باکس دسته را نشان می‌دهد.
- انتخاب «برچسب‌ها» فیلتر رول‌باکس پروژه + دسته + برچسب را نشان می‌دهد.
- فیلترها باید واقعاً روی فهرست کارهای Home اعمال شوند، نه صرفاً ظاهری باشند.
- کارت‌ها باید در RTL، روی عرض‌های معمول گوشی و اندازه‌های فونت مختلف بدون بریدگی، overflow یا ناپدیدشدن آیکون/نوشته کار کنند.
- رنگ‌های semantic موجود Arvin برای زمان، پروژه، دسته، برچسب، یادآور، خطا و حالت‌های انتخاب‌شده حفظ شوند.
## اصل عدم تخریب
- هیچ اصلاح UI نباید باعث حذف داده، تغییر ناخواسته شناسه canonical، ایجاد storage/model موازی یا حذف قابلیت‌های قبلی شود.
- قبل از حذف هر UI موجود، وابستگی کد و تست و مسیر داده بررسی شود.
- اگر رفتار یا نتیجه‌ای با CI/تست/گوشی واقعی اثبات نشده است، وضعیت «نامشخص» ثبت شود.
- تغییرات این قرارداد باید از مسیر Issue + Branch + PR انجام شوند و main مستقیماً تغییر نکند.
