# Arvin — Official Calendar Reminders

## تصمیم محصولی
دو منبع رسمی/مرجع باید به‌صورت یادآور در تقویم آروین قابل نمایش باشند:

1. **اوقات شرعی شیعه** بر مبنای روش/اطلاعات مرکز تقویم مؤسسه ژئوفیزیک دانشگاه تهران.
2. **تعطیلات رسمی ایران** بر مبنای تقویم رسمی کشور و مناسبت‌های مصوب، با استفاده از داده‌های مرکز تقویم مؤسسه ژئوفیزیک دانشگاه تهران.

این موارد بخشی از تجربه Calendar هستند و باید به‌عنوان reminderهای تقویمی قابل مشاهده باشند؛ اما نباید با Note timestamp، FollowUp یا Calendar Event کاربر مخلوط شوند.

## اوقات شرعی شیعه

### الزام
برای هر روز و مکان انتخاب‌شده، آروین باید اوقات شرعی شیعه را در تقویم به‌صورت reminderهای خواندنی نمایش دهد.

### اصل منبع
- مبنای محاسبه/داده باید روش مورد عمل شورای مرکز تقویم مؤسسه ژئوفیزیک دانشگاه تهران باشد.
- مؤسسه ژئوفیزیک اعلام کرده است که نظر اعضای شورای مرکز تقویم برای محاسبه اوقات شرعی مورد عمل قرار می‌گیرد.
- روش یا داده‌ای که صرفاً از یک سرویس عمومی دیگر گرفته شده باشد، بدون تطبیق با منبع مرجع، جایگزین این مبنا نشود.

### مکان
اوقات شرعی به مکان وابسته است. بنابراین طراحی باید یکی از این مسیرهای معتبر را داشته باشد:
- مکان فعلی دستگاه با اجازه کاربر؛ یا
- شهر/مکان انتخابی کاربر.

مختصات/مکان انتخاب‌شده باید در محاسبه روزهای بعدی نیز به‌صورت شفاف قابل مشاهده و تغییر باشد.

### نمایش پیشنهادی
برای هر روز، موارد مربوط به همان روز در بخش یادآورها نمایش داده شوند؛ از جمله زمان‌های ارائه‌شده توسط منبع مرجع مانند:
- صبح/فجر
- طلوع خورشید
- ظهر
- غروب
- مغرب
- نیمه‌شب شرعی

نام دقیق و مجموعه نهایی زمان‌ها باید بر اساس داده/روش مرجع انتخاب‌شده در مرحله پیاده‌سازی تثبیت شود و نباید از روی حدس ساخته شود.

## تعطیلات رسمی ایران

### الزام
تعطیلات رسمی ایران باید به‌عنوان reminder تقویمی در آروین نمایش داده شوند.

### منبع
مرجع داده باید **تقویم رسمی کشور** و مناسبت‌های مصوب شورای فرهنگ عمومی باشد؛ تقویم رسمی توسط شورای مرکز تقویم مؤسسه ژئوفیزیک دانشگاه تهران استخراج و تنظیم می‌شود.

### رفتار
- تعطیلات رسمی باید از یادآوری‌های کاربر قابل تشخیص باشند.
- تاریخ شمسی و عنوان فارسی نمایش داده شود.
- داده‌ها باید سال‌به‌سال قابل به‌روزرسانی باشند.
- تعطیلی رسمی با «مناسبت غیرتعطیل» اشتباه نشود.
- تغییرات یا اصلاحیه‌های رسمی باید قابلیت به‌روزرسانی داده تقویم را داشته باشند.

## مرزبندی داده

```text
Official Prayer Times
        ↓
Calendar Reminder Source

Official Iranian Holidays
        ↓
Calendar Reminder Source

User Item / Reminder / FollowUp
        ↓
Arvin source of truth
```

منابع رسمی تقویم نباید یک Database/Storage موازی برای Itemهای آروین ایجاد کنند. بهتر است این داده‌ها به‌عنوان providerهای خواندنی Calendar به مدل موجود `CalendarReminder` متصل شوند یا در صورت نیاز یک abstraction محدود و مشخص برای منابع تقویمی ایجاد شود.

## Google Calendar
نمایش این موارد داخل تقویم آروین به‌تنهایی به معنی ارسال آنها به Google Calendar نیست. انتقال به Google/system Calendar فقط در صورت تعریف صریح integration محصول انجام شود.

## Offline / Cache
برای تجربه قابل استفاده، پس از دریافت/محاسبه داده معتبر می‌توان cache محدود و قابل انقضا داشت؛ اما cache نباید منبع حقیقت مستقل شود. در نبود داده معتبر، آروین نباید زمان شرعی یا تعطیلی رسمی را حدس بزند.

## تست و پذیرش
قبل از Done شدن این قابلیت:
- تبدیل تاریخ شمسی/میلادی تست شود.
- timezone و ساعت محلی تست شود.
- مکان انتخابی و تغییر مکان تست شود.
- نمونه‌های اوقات شرعی با منبع مرجع تطبیق داده شوند.
- تعطیلات رسمی با نسخه رسمی همان سال تطبیق داده شوند.
- روزهای غیرتعطیل به‌اشتباه تعطیل نشوند.
- Calendar UI فعلی بدون بازنویسی غیرضروری حفظ شود.
- CI و APK واقعی تست شوند.
