# ماتریس تأیید منابع «پیام روز» آروین — 2026-08-27

Refs: #260

## اصل حاکم
منبع علمی معتبر با «مجوز استفاده production/API» یکی نیست. هیچ منبعی فقط به‌دلیل معتبر بودن علمی، dependency مستقیم محصول محسوب نمی‌شود.

| دسته | مرجع علمی/تطبیق پیشنهادی | نقش فعلی | شرط ورود به production |
|---|---|---|---|
| قرآن کریم | مرکز طبع و نشر قرآن جمهوری اسلامی ایران + مراکز معتبر قرآنی حوزوی | متن/تطبیق | متن/ترجمه قابل انتساب + مجوز بازنشر/روش دریافت روشن |
| حدیث شیعه | پژوهشگاه قرآن و حدیث/دارالحدیث + جامع‌الاحادیث نور | مأخذ و تطبیق | گوینده + کتاب + شماره/جلد/صفحه + وضعیت اعتبار در صورت وجود + اجازه استفاده |
| نهج‌البلاغه | منابع حوزوی معتبر قم/نجف + پایگاه‌های علمی شیعی | تطبیق خطبه/نامه/حکمت | فراز مستقل + شماره دقیق + ترجمه مجاز |
| صحیفه سجادیه | پژوهشگاه قرآن و حدیث و منابع حوزوی معتبر | تطبیق دعا/فراز | شماره دعا/فراز + ترجمه مجاز |
| بزرگان ایران | اثر اصلی یا مؤسسه رسمی نشر آثار هر شخصیت | منبع اولیه | مأخذ مشخص و حق استفاده روشن |
| بزرگان جهان | اثر/سخنرانی/آرشیو اولیه قابل راستی‌آزمایی | منبع اولیه | متن اصلی + مأخذ + ترجمه کنترل‌شده |

## Guardrails
- scraping مستقیم سایت‌های حوزوی یا مؤسسات رسمی، بدون اجازه/قرارداد روشن، provider production نیست.
- API عمومی ناشناس یا aggregator نقل‌قول، منبع اعتبار حدیث/قرآن محسوب نمی‌شود.
- ترجمه ماشینی متن دینی به‌عنوان ترجمه نهایی publish نمی‌شود.
- «در کتاب شیعی آمده» به‌تنهایی معادل «صحیح‌السند» نیست.
- اگر source/reference/verification ناقص باشد آیتم باید fail-closed شود.
- بسته‌های محتوا کوچک و versioned می‌مانند؛ کتاب کامل وارد APK نمی‌شود.

## وضعیت اجرایی
- لایه مدل و selector در main موجود است.
- UI، codec، preferences و notification به‌صورت PRهای مستقل در حال validation هستند.
- انتخاب provider واقعی تا تأیید روش دسترسی/مجوز از توسعه UI جدا نگه داشته می‌شود تا delivery متوقف نشود.

## اقدام بعدی منبع
برای هر دسته باید یک «source adapter approval record» ثبت شود که شامل نام مؤسسه، endpoint/روش دریافت، شرایط استفاده، تاریخ بررسی و مسئول تأیید باشد. تا قبل از آن، محتوای نمونه production محسوب نمی‌شود.
