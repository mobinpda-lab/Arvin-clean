# سند مرجع طراحی رابط کاربری آروین (Canonical UI Reference)

وضعیت: مرجع اصلی طراحی رابط کاربری

این سند قرارداد اصلی ظاهر و رفتار رابط آروین است و در تعارض با اسناد قدیمی UI اولویت دارد.

## اصل مرجع
تصاویر نصب واقعی آروین که توسط مالک پروژه ارائه شده‌اند، به عنوان مرجع چیدمان، حس بصری، رنگ‌بندی، فاصله‌ها، جایگذاری کنترل‌ها و تجربه کاربری استفاده می‌شوند؛ اما داده، متن و وضعیت‌ها باید از مدل واقعی برنامه تولید شوند.

## جلوگیری از تداخل اسناد قدیمی
- الزام نمایش چهار کارت آماری در صفحه خانه منسوخ است.
- تصاویر قدیمی فقط مرجع تعامل هستند و نباید باعث بازگشت طراحی‌های حذف‌شده شوند.
- هیچ UI جدیدی نباید مدل یا ذخیره‌سازی موازی برای شباهت ظاهری ایجاد کند.

## قرارداد ظاهر مشترک
- فارسی و RTL.
- فونت مصوب VazirHarf v34.003.
- رنگ اصلی: #4A4CAB.
- پس‌زمینه روشن، کارت سفید، گوشه نرم، سایه ظریف.
- آیکون‌ها هماهنگ و دارای معنای عملکردی.

## صفحه اصلی
ساختار:
1. عنوان مذهبی: «بسم الله الرحمن الرحیم».
2. عنوان برنامه: «مدیریت کارها و پیگیری آروین».
3. اعلان در چپ، منو در راست.
4. جستجوی گرد.
5. چهار ورودی گروه‌بندی ثابت:
   - زمان
   - پروژه‌ها
   - دسته‌ها
   - برچسب‌ها

این چهار مورد ابزار تغییر نمایش واقعی داده هستند، نه کارت آماری.

## کارت کار
شامل:
- وضعیت انجام.
- عنوان برجسته.
- ارتباط با پروژه/دسته.
- موعد واقعی.
- آخرین پیگیری یا خلاصه توضیح.
- تاریخ و ساعت پیگیری به صورت کم‌رنگ.

لمس کارت باید جزئیات را باز کند.

## ورود سریع
ورودی سریع باید:
- پنل پایین صفحه و بالای صفحه‌کلید باشد.
- ثبت پیاپی را بدون بستن پنل پشتیبانی کند.
- بعد از ثبت موفق فقط داده مخصوص کار جدید را پاک کند.
- انتخاب‌های پروژه، دسته، برچسب، موعد، یادآوری و تکرار را حفظ کند.
- از ثبت تکراری جلوگیری کند.

## کار پیگیری‌دار
مرجع شامل:
- اطلاعات کامل کار.
- کارت آخرین پیگیری.
- تاریخچه واقعی پیگیری‌ها.
- افزودن پیگیری بدون حذف تاریخچه.

## دفترچه
دو حالت مستقل:
- یادداشت ساده.
- چک‌لیست.

ویرایشگر یادداشت باید محتوامحور و تمام‌صفحه باشد.

## منوی پایین
پنج مقصد ثابت:
- خانه.
- تقویم.
- دفترچه.
- اقدام بعدی.
- بیشتر.

## کنترل کیفیت
قبل از انتشار باید بررسی شود:
- ثبت سه کار پشت سر هم.
- حفظ داده پس از اجرای مجدد.
- چهار گروه‌بندی واقعی.
- تاریخچه پیگیری.
- حفظ یادداشت‌ها.
- وضعیت‌های خالی، خطا، بارگذاری و اندازه متن بزرگ.

## وضعیت فعلی
این فایل قرارداد طراحی است و باید مبنای اصلاح UI، تست پذیرش و بررسی PRهای آینده باشد.
