# تصمیم معماری FollowUp — تاریخ بدون ساعت

تاریخ: 2026-08-15

## هدف
کاربر باید بتواند برای یک Item در یک روز مشخص، FollowUp ثبت کند بدون اینکه ساعت برای آن اجباری باشد.

## قرارداد
- تاریخ FollowUp اجباری است.
- ساعت FollowUp برای کاربر اختیاری است.
- حالت بدون ساعت با مفهوم **تمام‌روز / Date-only** نمایش داده می‌شود.
- مقدار `00:00` نباید به‌عنوان ساعت واقعیِ پیگیری بدون ساعت به کاربر نمایش داده شود.
- Reminder مربوط به Next FollowUp یک مفهوم مستقل است و می‌تواند ساعت داشته باشد.
- FollowUp همچنان بخشی از همان Item و `FollowUps[]` است و Storage/Database موازی ایجاد نمی‌شود.

## محدودیت معماری
مدل فعلی FollowUp دارای `DateTime` است؛ بنابراین پیاده‌سازی UI و Persistence باید بدون شکستن داده‌های قدیمی انجام شود. قبل از تغییر Model/Persistence باید migration، serialization، Home، Calendar، Widget، PDF/Print و تست‌های مرتبط بررسی شوند.

## نمایش پیشنهادی
- دارای ساعت: `۱۴۰۵/۰۵/۲۴ | ۱۰:۳۰`
- بدون ساعت: `۱۴۰۵/۰۵/۲۴ | تمام‌روز`

## مراحل اجرای بعدی
1. تکمیل قرارداد Model/Persistence با backward compatibility.
2. افزودن UI انتخاب «تمام‌روز».
3. اصلاح نمایش Home/FollowUp و خروجی‌ها برای حذف ساعت جعلی.
4. حفظ استقلال Reminder.
5. تست focused و regression.
6. Build + Parallel Workflow و بررسی APK.

این سند فقط تصمیم و قرارداد را ثبت می‌کند و جایگزین Foundation موجود نمی‌شود.
