# Product-first autonomous queue

The five-minute autonomous queue remains enabled.

When an open product Wave pull request exists, the queue defers competing AI issue dispatches. This prevents duplicate implementations while the active product branch is being completed.

The queue remains fail-closed for manual, security, and escalated stops. Factory work is a supporting mechanism, not the product goal.

## Final Product Lock — Issue #1295
**Product First:** factory/NIRA/automation are means; Arvin Release-Ready is the only final objective.

When an open finalization product PR exists, automation must not create competing implementation work. It must preserve the active product lane, assist validation, recovery and evidence, and continue from the latest GitHub checkpoint.

Locked sequence: G0 Baseline → G1 Storage/Migration → G2 Home → G3 Quick Capture → G4 Keyboard/Back → G5 FollowUp → G6 Swipe → G7 Notebook → G8 Calendar → G9 More/Settings → G10 Verification → G11 Android Evidence → G12 Finalize.

Legacy Home is excluded from data migration. Only durable user data migrates; legacy Home code/test dependencies are corrected in the corresponding product wave.

Five-minute execution remains the default: inspect exact-head → one measurable product delta/validation → targeted test → checkpoint. Automation must never treat workflow health, issue creation or PR creation as product completion.

Continuity: after any ChatGPT conversation/account/session change, resume from the latest valid checkpoint and exact-head in GitHub; do not restart the project audit.
