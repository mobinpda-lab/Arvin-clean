# قرارداد نهایی رابط و رفتار آروین

تاریخ مرجع: ۱۴۰۵/۰۶/۲۹
مرجع محصول: مشخصات نهایی مالک در ۲۰۲۶-۰۹-۲۰
وضعیت: قرارداد اجرایی و معیار پذیرش

## تقدم مرجع

این سند مرجع اجرایی جدید برای رابط و رفتار محصول است. در تعارض مستقیم، این سند بر قراردادهای قدیمی UI مقدم است؛ معماری، مدل داده، TaskStore، ProjectStore، CanonicalNotebookRepository و داده‌های موجود کاربران حفظ می‌شوند. مستندات قدیمی حذف نمی‌شوند و فقط در صورت تعارض به این سند ارجاع داده می‌شوند.

## Home

Home یک صفحه با چهار حالت داده‌ای است:
1. زمان
2. پروژه‌ها
3. دسته‌ها
4. برچسب‌ها

چهار حالت با چهار دکمه هم‌اندازه و آیکون‌دار در زیر جست‌وجو انتخاب می‌شوند و مسیر یا Storage جداگانه ندارند. شمارنده داخل دکمه‌ها ممنوع است.

در Home موارد زیر نمایش داده نمی‌شوند:
- کارت‌های آماری کل، فعال، انجام‌شده و عقب‌افتاده
- عنوان «کارهای من»
- «مشاهده همه» مربوط به ساختار قدیمی
- کشویی «گروه‌بندی:»
- کشویی مرتب‌سازی شلوغ

فیلترهای کاری در «بیشتر» باقی می‌مانند.

## گروه‌بندی

- زمان فقط از Task.dueDate استفاده می‌کند: عقب‌افتاده، امروز، آینده، بدون موعد.
- پروژه‌ها از ProjectStore و شناسه‌های واقعی Task استفاده می‌کنند؛ «بدون پروژه» اجباری است.
- دسته‌ها از Task.category استفاده می‌کنند؛ «بدون دسته» اجباری است.
- برچسب‌ها از Task.tags استفاده می‌کنند و یک Task چندبرچسبی در Storage تکثیر نمی‌شود؛ «بدون برچسب» اجباری است.
- Reminder، FollowUp، نماز و رویداد رسمی شمارش Due Date را تغییر نمی‌دهند.

## کارت Task

هر کارت شامل انجام‌شدن، عنوان، پروژه/دسته، موعد در صورت وجود، وضعیت و برچسب‌های محدود است. لمس کارت باید جزئیات Task را باز کند.

متن ثانویه:
- اگر FollowUp واقعی وجود دارد، متن آخرین FollowUp نمایش داده می‌شود؛ متن خالی به «پیگیری» تبدیل می‌شود.
- در غیر این صورت یک خط از توضیحات نمایش داده می‌شود.
- متن حداکثر یک خط است و با … کوتاه می‌شود.

## ثبت سریع

ثبت سریع باید Bottom Sheet واقعی باشد، نه AlertDialog. عنوان تنها برای ثبت کافی است و تاریخ، ساعت، یادآور و اولویت نباید خودکار اضافه شوند. پس از ثبت موفق، مسیر ثبت پشت‌سرهم باید پنجره، فوکوس و کیبورد را حفظ کند و داده‌ها فقط از TaskStore مرکزی عبور کنند.

Back اندروید:
- زیرمنوی باز ابتدا بسته می‌شود.
- پیش‌نویس خالی بدون خروج از برنامه بسته می‌شود.
- پیش‌نویس غیرخالی گزینه‌های ثبت و خروج، خروج بدون ثبت و ادامه نوشتن دارد.

## Swipe

Swipe باید در RTL واقعی آزمایش شود و تنظیمات چپ/راست در AppSettingsService باقی می‌ماند. حذف عادی به Trash می‌رود و حذف دائمی فقط با تأیید صریح انجام می‌شود. Undo باید در مسیر Trash/Swipe تأیید شود.

## FollowUp

FollowUpها در Task.followUps[] باقی می‌مانند. ثبت جدید append است و تاریخچه قبلی حذف یا بازنویسی نمی‌شود. جزئیات Task باید تاریخچه را از جدیدترین به قدیمی‌ترین نشان دهد و Home متن آخرین FollowUp واقعی را نمایش دهد.

## Notebook

یادداشت ساده و چک‌لیست دو حالت UX مستقل هستند ولی از زیرساخت CanonicalNotebookRepository و TaskStore موجود استفاده می‌کنند. Storage موازی مجاز نیست. جابه‌جایی دسته نباید شناسه را تغییر دهد.

## Calendar و Navigation

تقویم شمسی واقعی، ایجاد Task با نگه‌داشتن روی روز، داده واقعی و همگام‌سازی انتخابی تقویم دستگاه الزامی است. نماز و قابلیت‌های سالم موجود نباید بدون دلیل تغییر کنند.

منوی پایین دقیقاً پنج مقصد دارد:
خانه | تقویم | دفترچه | اقدام بعدی | بیشتر

# الحاقیه اجرایی نهایی مالک — ۱۴۰۵/۰۶/۳۱

این الحاقیه، الزامات اجرایی تکمیلی مالک را به قرارداد اصلی اضافه می‌کند و در تعارض با اسناد قدیمی مقدم است. هیچ‌یک از الزامات این الحاقیه صرفاً با مستندسازی انجام‌شده تلقی نمی‌شوند؛ معیار تکمیل همان کد واقعی + آزمون + Build + شواهد Android روی همان SHA است.

## ۱. شروع هر موج اجرا

قبل از هر تغییر باید وضعیت زنده `main`، SHA، شاخه کاری، PRهای باز، Issues و GitHub Actions بررسی شود. سپس مدل‌های داده، TaskStore، ProjectStore، سرویس‌های گروه‌بندی، Notebook، Calendar، FollowUp و Settings و اسناد مرجع بررسی شوند. منابع مرجع شامل:
- `docs/ARVIN_UI_CANONICAL.md`
- `docs/ARVIN_USER_REQUIREMENTS_MEMORY_۱۴۰۵/۰۶/۲۶.md`
- `docs/ARVIN_WAVE1_HOME_GROUPING_EXECUTION_LOG.md`
- `docs/ARVIN_HOME_GROUPING_PHASE2_REAL_DATA_MAPPING.md`
- اسناد Home، Quick Capture، FollowUp، Notebook و Calendar
- `docs/ui-reference/` فقط در صورت وجود واقعی تصاویر.

اگر تصاویر مرجع وجود نداشته باشند، همین قرارداد مرجع است و طراحی بر اساس حدس انجام نمی‌شود. قبل از کدنویسی باید تعارض‌ها و فایل‌های درگیر مشخص شوند.

هیچ مدل، Repository، Storage، قابلیت یا مسیر موازی ساخته نشود. داده‌های Task، FollowUp، Project، Category، Tag، Note، Checklist، Archive و Trash باید حفظ شوند. هر تغییر داده‌ای باید Migration سازگار و آزمون داشته باشد.

## ۳. Home — جزئیات قطعی

ساختار: کپسول «بسم الله الرحمن الرحیم»، عنوان «مدیریت کارها و پیگیری آروین»، اعلان در سمت فیزیکی چپ، منو در سمت فیزیکی راست، جست‌وجو، دقیقاً چهار دکمه گروه‌بندی، حالت انتخاب‌شده، داده واقعی، FAB و پنج مقصد پایین.

در Home نباید کارت‌های «کل»، «فعال»، «انجام‌شده»، «عقب‌افتاده»، عنوان «کارهای من»، «مشاهده همه» قدیمی، کشویی `home-group-mode-selector` یا مرتب‌سازی شلوغ ردیف اصلی نمایش داده شوند. فیلترهای قدیمی می‌توانند در «بیشتر» باقی بمانند.

چهار دکمه دقیقاً این ترتیب RTL را دارند: زمان، پروژه‌ها، دسته‌ها، برچسب‌ها. هرکدام هم‌اندازه و آیکون‌دار هستند و شمارنده ندارند. رنگ آیکون در حالت انتخاب‌شده حفظ می‌شود و خود حالت با رنگ اصلی آروین مشخص می‌شود. این‌ها چهار حالت همان Home هستند، نه چهار صفحه یا Storage مستقل.

نمای زمان فقط از `Task.dueDate` استفاده می‌کند: عقب‌افتاده، امروز، آینده و بدون موعد؛ آینده در صورت نیاز به فردا/این هفته/بعدتر تقسیم می‌شود. Reminder، FollowUp، نماز و رویداد رسمی جای Due Date را نمی‌گیرند و Task انجام‌شده عقب‌افتاده نیست.

نمای پروژه‌ها از ProjectStore واقعی استفاده می‌کند، «بدون پروژه» دارد، هر Task حداکثر یک پروژه دارد، + کنار پروژه همان پروژه را به Draft ساخت Task منتقل می‌کند، و حذف پروژه Taskهای آن را حذف نمی‌کند.

نمای دسته‌ها مستقل از پروژه است، «بدون دسته» دارد، مدیریت ساخت/ویرایش/حذف امن دارد و حذف دسته Task را حذف نمی‌کند. فیلتر بر اساس پروژه در صورت وجود باید از داده مرکزی استفاده کند.

نمای برچسب‌ها چندبرچسبی است؛ Task می‌تواند در چند گروه دیده شود ولی در Storage تکثیر نمی‌شود. «بدون برچسب» الزامی است و فیلتر پروژه/دسته در صورت ارائه باید روی داده واقعی باشد.

## ۴. کارت Task

کارت حداقل انجام‌شدن، عنوان، پروژه/دسته، موعد، وضعیت و برچسب‌های محدود را نشان می‌دهد و با لمس به Detail می‌رود، نه مستقیم به Edit.

متن ثانویه:
- وجود FollowUp → متن آخرین FollowUp واقعی.
- متن خالی FollowUp → «پیگیری».
- نبود FollowUp → یک خط توضیحات.
- حداکثر یک خط و با ellipsis.
- تاریخ/ساعت FollowUp جدا و کم‌اهمیت‌تر است.
صرف نمایش تاریخ آخرین FollowUp کافی نیست.

## ۵. Quick Capture / Bottom Sheet

Quick Capture باید Bottom Sheet واقعی باشد و از پایین صفحه، بالای کیبورد و با RTL باز شود. عنوان، تمرکز روی عنوان، فیلد بزرگ، «ثبت کار» و «فرم کامل» الزامی‌اند. تاریخ، ساعت، پروژه، دسته، برچسب، یادآور و تکرار اختیاری‌اند و Task عادی نباید مقدار خودکار بگیرد.

ثبت پشت‌سرهم باید از همان TaskStore مرکزی انجام شود؛ پنجره بسته نشود، عنوان و داده اختصاصی قبلی پاک شود، انتخاب‌های عمومی منطقی حفظ شوند، فوکوس و کیبورد باقی بمانند، Home به‌روز شود و پیام کوتاه «کار ثبت شد» نمایش داده شود. ثبت خالی و دوباره سریع جلوگیری شود و در خطا متن و انتخاب‌ها حفظ شوند.

Back: زیرمنوی باز ابتدا بسته شود؛ Draft خالی Bottom Sheet را ببندد و برنامه را نبندد؛ Draft غیرخالی گزینه‌های «ثبت و خروج»، «خروج بدون ثبت»، «ادامه نوشتن» داشته باشد. این رفتار باید با Android واقعی/Integration Test بررسی شود.

«فرم کامل» باید همان Draft و همان شناسه را ادامه دهد؛ مسیر دوم برای ساخت Task مجاز نیست؛ بازگشت یا لغو نباید Task تکراری بسازد و Draft را بی‌دلیل از بین ببرد. فرم کامل عنوان، توضیحات، تاریخ، ساعت، یادآور، تکرار، پروژه، دسته، برچسب، چک‌لیست و یادداشت اختیاری را در همان مسیر canonical ارائه می‌کند.

## ۶. Swipe

Swipe باید در RTL واقعی روی Android آزمایش شود. عملیات شامل انجام‌شدن، تغییر تاریخ/انتقال به امروز، جابه‌جایی پروژه یا دسته و انتقال به Trash است. جهت چپ/راست از Settings قابل انتخاب است. حذف عادی = Trash، حذف دائمی = تأیید صریح، و Undo باید واقعی و آزموده باشد. مسیرهای موجود archive/trash/moveToToday حفظ و complete/date-change تکمیل شوند. جهت نهایی باید در گزارش تحویل دقیقاً اعلام شود.

## ۷. Task Detail و FollowUp

Detail باید عنوان، پروژه، دسته، وضعیت، توضیحات، موعد، یادآور، برچسب‌ها، کارت آخرین FollowUp، تعداد و تاریخچه FollowUpها را از جدید به قدیم، Edit و Complete و + گرد افزودن FollowUp نشان دهد.

افزودن FollowUp تاریخ/ساعت فعلی را پیش‌فرض می‌کند ولی قابل ویرایش است؛ متن خالی به «پیگیری» canonicalize می‌شود؛ FollowUp جدید append می‌شود و هیچ سابقه‌ای بازنویسی/حذف نمی‌شود. بعد از موفقیت Detail و Home به‌روز می‌شوند و در خطا ورودی حفظ می‌شود. Edit/Complete تاریخچه را حذف نمی‌کند.

## ۸. Notebook

پایین‌ناو دقیقاً «خانه، تقویم، دفترچه، اقدام بعدی، بیشتر» است. Notebook عنوان «دفترچه» و زیرعنوان «یادداشت‌ها و چک‌لیست‌ها»، Search، فیلتر دسته، انتخاب Note/Checklist، کارت عنوان/پیش‌نمایش/دسته/تاریخ، + و Trash/Restore را فراهم می‌کند.

Simple Note باید تمام‌صفحه یا نزدیک آن، محتوامحور و آرام باشد و عنوان، تاریخ، دسته، متن، Save/Back/Move/Delete را در دسترس داشته باشد. کنترل Checklist/Deadline/Priority/FollowUp پیش‌فرض نباشد. ابزار قالب‌بندی فقط وقتی نمایش داده شود که واقعاً ذخیره پایدار دارد.

Checklist حالت UX مستقل دارد، عنوان و دسته، تعداد انجام‌شده/کل، درصد واقعی، افزودن/ویرایش/حذف/تیک و progress واقعی دارد. مثال ۲ از ۵ = ۴۰٪. جابه‌جایی دسته باید همان Task ID را حفظ کند. فقط `CanonicalNotebookRepository` و `TaskStore` استفاده شوند.

## ۹. Calendar

Calendar باید شمسی واقعی با نماهای روزانه، هفتگی، ماهانه و در صورت سالم بودن سالانه باشد؛ حرکت بین بازه‌ها، Today، انتخاب مستقیم تاریخ و Long-press برای ساخت Task با همان تاریخ را داشته باشد. Task، FollowUp، Reminder، مناسبت رسمی و رویداد دستگاه باید قابل تشخیص باشند و داده واقعی نمایش داده شود.

همگام‌سازی انتخابی با Calendar دستگاه باید از زیرساخت موجود استفاده کند. خواندن رویدادها در صورت فعال‌بودن تنظیمات، ویرایش/تبدیل رویداد دستگاه فقط با تأیید کاربر. قابلیت‌های سالم تقویم و نماز بدون دلیل تغییر نکنند.

## ۱۰. اقدام بعدی و بیشتر

اقدام بعدی فقط از Task واقعی پیشنهاد می‌سازد، دلیل قابل فهم دارد و به Detail همان Task می‌رود؛ پیشنهاد ساختگی/AI نمایشی ممنوع است. Taskهای تکمیل، بایگانی و حذف‌شده نمایش داده نشوند.

«بیشتر» باید مسیر واقعی به کارهای من و فیلترهای کل/فعال/انجام‌شده/عقب‌افتاده، امروز، بدون موعد، پروژه‌ها، دسته‌ها، برچسب‌ها، دفتر پیگیری/منتظر پاسخ، گزارش‌ها، بایگانی، Trash، Backup/Restore، Settings، Help و About را فراهم کند. صفحه مستقل موجود باید همان صفحه متصل شود و نسخه موازی ساخته نشود.

## ۱۱. Settings

تنظیمات واقعی و فعال: System/Light/Dark، VazirHarf، اندازه متن، تاریخ فارسی، Swipe چپ/راست، اعلان و مجوز، FollowUp خودکار فقط در صورت منطق واقعی، Calendar/Sync، Backup/Restore، Privacy، Help/About و مدیریت Project/Category/Tag. گزینه بدون عملکرد واقعی نباید در UI نمایش داده شود.

## ۱۲. مستندات

## ۱۳. آزمون‌های اجباری

Home: نبود چهار کارت قدیمی و «کارهای من»، وجود چهار حالت، آیکون و selected state، تغییر واقعی همان صفحه، عدم تکثیر Task چندبرچسبی و مسیر مشخص برای بدون پروژه/دسته/برچسب/موعد و نمایش یک‌خطی آخرین FollowUp/Description.

Quick Capture: سه Task پشت‌سرهم بدون بسته‌شدن، پاک‌شدن و refocus، جلوگیری از خالی/duplicate، حفظ ورودی در خطا، حفظ Draft در Full Form، Back خالی/غیرخالی و Android keyboard/Back.

FollowUp: blank→پیگیری، append، ترتیب جدید→قدیم، حفظ تاریخچه هنگام Edit، و به‌روزرسانی Home.

Notebook: دو حالت مستقل UI با Storage مرکزی، same-ID category move، progress صحیح، Trash/Restore.

Calendar/Swipe: dueDate-only grouping، جهت RTL، Undo، نماهای شمسی و Long-press ساخت Task.

## ۱۷. مرز Migration و Legacy Home

Legacy Home، selectorها، فیلترهای قدیمی، projectionهای سازگاری UI، تست‌های صرفاً مربوط به UI قدیمی و فایل‌های صرفاً UI/Widget، «داده مهاجرتی» نیستند. Migration فقط داده واقعی و قراردادهای پایدار کاربر را منتقل می‌کند.

هیچ Storage/Model موازی برای حفظ Legacy Home ساخته نشود. وابستگی‌های کد و آزمون به Home قدیمی باید در موج UI خود اصلاح شوند. Migration نباید UI قدیمی را به مقصد SQL تبدیل کند.

## ۱۸. Gate ذخیره‌سازی و Migration

مهاجرت به SQLite + Drift فقط پس از اثبات lossless بودن مسیر مجاز است. SharedPreferences قدیمی تا پایان اثبات و امکان rollback نباید overwrite/delete شود. IDها باید حفظ شوند، duplicate ممنوع است، Backup قبلی باید قابل Restore بماند و round-trip داده باید آزموده شود.

در وضعیت فعلی، Issue #1340 یک Gate باز است: `TaskMigrationAdapter` هنوز برای کلیدهای ناشناخته JSON تضمین lossless ندارد و قبل از تصمیم/آزمون round-trip نباید cutover واقعی TaskStore انجام شود.


## قانون اجرایی جدید — SQL محور اصلی فعلی

از ۱۴۰۵/۰۶/۳۱، SQL/SQLite + Drift فقط یک مرحله مستنداتی نیست و یکی از محورهای اصلی اجرای فعلی تکمیل آروین است.

### برنامه مرجع ادامه پروژه
1. حسابرسی زنده GitHub، شاخه/PR/SHA/Actions و وضعیت واقعی کد.
2. تثبیت پایه Drift و Schema بدون ساخت Model/Storage موازی.
3. رفع کامل گیت Lossless Migration؛ حفظ شناسه، Task، FollowUp و تاریخچه، Project، Category، Tag، Checklist، Note، Archive و Trash و هر داده‌ای که در مرز مهاجرت وجود دارد.
4. مهاجرت واقعی SharedPreferences/JSON به SQLite، با اعتبارسنجی، شمارش، روابط، جلوگیری از duplicate، idempotency و rollback.
5. اجرای round-trip و Backup/Restore و اثبات عدم از دست رفتن داده.
6. انتقال کنترل‌شده Repository/TaskStore به SQL به‌عنوان مسیر اصلی ذخیره‌سازی.
7. اجرای Analyze، Test، Debug APK و Release APK روی همان SHA و سپس شواهد Android.
8. تکمیل و تأیید Home نهایی، Quick Capture، FollowUp، Notebook، Calendar، Next Action، More، Settings و Swipe با داده واقعی و بدون مسیر موازی.
9. فقط پس از عبور همه گیت‌ها، اعلام Release-Ready؛ هیچ مرحله‌ای با «ساخت Schema» یا «سبز شدن CI قدیمی» کامل محسوب نمی‌شود.

### مرز قطعی Legacy Home
Home قدیمی، home-group-mode-selector، فیلترها/کنترل‌های قدیمی، projectionهای سازگاری، تست‌های صرفاً UI قدیمی و فایل‌های صرفاً UI/Widget داده مهاجرتی نیستند و نباید به SQL منتقل شوند. Migration فقط داده واقعی کاربر را منتقل می‌کند.
