# Arvin — Prayer Reminder Offline-First Contract

تاریخ: 2026-08-15

## تصمیم محصول
هشدارهای اوقات شرعی آروین نباید برای اجرای زمان‌بندی‌شده خود به اینترنت وابسته باشند. اینترنت فقط برای دریافت/به‌روزرسانی داده معتبر اوقات شرعی لازم است؛ اجرای Reminderهای از قبل زمان‌بندی‌شده باید روی خود دستگاه انجام شود.

## قرارداد رفتاری
- اوقات شرعی معتبر برای شهر/مکان و تاریخ موردنظر باید پیش از زمان هشدار دریافت یا محاسبه و روی دستگاه ذخیره شوند.
- Reminder زمان‌بندی‌شده باید با داده محلی و Scheduler/Notification سیستم اجرا شود.
- قطع اینترنت پس از زمان‌بندی نباید هشدار را متوقف کند.
- اگر برای شهر/تاریخ جدید داده معتبر محلی وجود نداشته باشد، آروین نباید زمان حدسی تولید کند؛ باید وضعیت نیازمند به‌روزرسانی را اعلام کند.
- تغییر شهر، timezone یا منبع داده باید باعث بازاعتبارسنجی و در صورت نیاز زمان‌بندی مجدد شود.
- داده اوقات شرعی باید به CalendarReminder موجود متصل شود و Storage موازی ایجاد نکند.

## معماری موردنظر
`Official Prayer Provider → validated local cache → CalendarReminder → device scheduler/notification`

این قرارداد مستقل از UI است و باید در Provider، persistence، scheduler و تست‌های regression/E2E منعکس شود.

## دامنه خارج از این تصمیم
این سند هنوز یک Provider واقعی را پیاده‌سازی نمی‌کند و هیچ زمان شرعی را حدس نمی‌زند. منبع رسمی و Provider واقعی باید مطابق Roadmap و مستندات Calendar پروژه تکمیل و تست شوند.

## تست‌های الزامی برای Done
1. دریافت موفق داده و زمان‌بندی Reminder.
2. قطع اینترنت بعد از زمان‌بندی و دریافت هشدار در زمان مقرر.
3. نبود داده معتبر برای شهر/تاریخ جدید بدون تولید زمان جعلی.
4. تغییر شهر/timezone و باززمان‌بندی صحیح.
5. regression برای CalendarReminder و Reminderهای عادی.
6. تأیید APK واقعی و CI سبز قبل از اعلام Done.
